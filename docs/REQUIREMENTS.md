# Emby Clean 重构需求文档

> 状态：Draft v0.1，基于当前仓库代码、README/产品说明，以及已知 FNOS 媒体链路整理。
> 本文用于下一轮需求沟通，不代表所有设计已经确认。

## 1. 项目定位

Emby Clean 是一个部署在 FNOS/Docker 上的 Emby 资料库盘点、查重、筛选和安全清理应用。

它解决的问题不是“只查某一种日本资源番号”，而是对多个 Emby 资料库中的媒体、文件、元数据和图片进行分层识别：

1. 找出确定重复、疑似重复和质量/完整性异常的资源。
2. 用可解释的规则给出保留、删除或人工复核建议。
3. 让用户在删除前看到完整证据，并通过可恢复、可审计的执行流程处理结果。
4. 与 FNOS 现有的 CMS、MDC、CloudDrive2/115、Emby 分工协作，不重复写入元数据或破坏 STRM/挂载链路。

## 2. 当前版本基线（已从代码确认）

### 2.1 当前技术形态

- 单容器 Docker 服务，Python 3.12、FastAPI、httpx、APScheduler、SQLite。
- Web 入口由 `app/main.py` 提供，前端集中在 `app/static/index.html`。
- `/data` 保存 SQLite、配置备份、日志和删除队列；默认端口 `19898`。
- 当前是单 Emby 实例模型，使用 Emby API 认证、同步资料库和执行删除。
- 当前没有测试目录，规则、API、删除 worker 和前端行为缺少自动化回归保护。

### 2.2 已有能力

- Emby 连接、登录、Token 自动重新认证。
- 媒体库发现、分页同步、本地缓存和失效缓存清理。
- 扫描模式：
  - AV 番号/编码重复；
  - 忽略画质与版本标签后的智能名称重复；
  - 文件大小相同；
  - 时长相同或近似（当前主要为同目录/全库）；
  - 缺失封面；
  - 极小文件；
  - 缺失 Provider ID；
  - 缺失字幕轨道；
  - 空媒体库。
- 结果按组展示，默认勾选推荐删除项，支持忽略、人工复核、打开 Emby 条目。
- 串行删除队列：删除后轮询确认 Emby 条目消失，再删除本地缓存；失败重试。
- 删除完成后可触发 Emby 全库刷新，并通过 Webhook 通知。
- 定时同步、定时扫描、可选自动入队删除。
- 配置导入/导出、配置备份恢复、日志、存储统计和移动端页面。

### 2.3 当前明确缺口

- 查重规则与 AV 专用启发式耦合，欧美、动画、电视剧、纪录片、演唱会、课程等资料库缺少通用身份策略。
- 当前“图片检查”只判断 Emby 是否存在 Primary image，不比较图片内容，也没有 Poster/Backdrop/Logo/Thumb 分类。
- 没有内容指纹：文件 hash、媒体流指纹、音视频指纹、图片感知 hash 均未实现。
- 不能区分“同一文件被多个 Emby 条目引用”“同内容不同文件”“同作品不同版本”。
- 未形成可配置的候选分层、相似度评分、证据解释和规则版本记录。
- 删除动作仍以 Emby API 为中心，没有 FNOS/STRM/云盘资源的删除策略、路径安全校验、隔离区或回滚设计。
- 凭据以配置/备份形式持久化，缺少更明确的机密保护、应用认证和权限模型。
- 任务、同步和扫描以单进程内存锁为主，缺少可恢复任务状态、暂停/继续、分阶段进度和大库性能策略。

## 3. FNOS 架构约束与职责边界

以下边界基于已知 FNOS 链路，正式实施前仍需对当前部署做一次只读复核。

```text
资源发现/下载层 -> CloudMediaSynC / CMS -> MDC 识别、整理、写 NFO/图片 -> Emby 索引与播放
                                      \-> Emby Clean 盘点、查重、筛选、审计、清理
```

### 3.1 Emby Clean 应负责

- 通过 Emby API 获取资料库、媒体条目、媒体源、媒体流、Provider ID、图片标签和用户数据。
- 可选地以只读方式访问 FNOS 媒体路径，采集文件系统证据和内容指纹。
- 建立统一资源索引，运行查重/质量/完整性规则，保存扫描历史和证据。
- 提供人工审核、保留策略、删除计划、通知和操作审计。
- 通过 API 或受控 webhook 触发一次必要的 Emby 刷新。

### 3.2 Emby Clean 不应负责

- 不替代 MDC 写 NFO、图片、演员和导演元数据。
- 不替代 CMS 管理 STRM、115/云盘同步和 302 播放入口。
- 不直接读写 Emby 内部数据库。
- 不默认扫描、下载或转码所有云端媒体；对 STRM/远程资源必须支持“不可计算指纹”的明确状态。
- 不在没有明确删除策略时自动删除源文件、云盘文件或共享目录内容。

### 3.3 需要重点保护的 FNOS 场景

- `/media` 可能同时被 Emby、MDC 使用，CMS 使用自己的容器路径映射；应用必须保存“宿主机路径、容器路径、Emby 展示路径”的映射关系。
- STRM、NFO、图片和真实云端文件可能不是同一个删除对象；删除 Emby 条目不能自动等价为删除真实资源。
- MDC 是 NFO/图片的主要写入者，Emby Clean 只读这些结果并报告缺失/冲突，不应形成第二个元数据写入源。
- 删除或整理操作必须能区分本地实体文件、STRM 文件、目录项、远程 CloudDrive/115 引用和仅存在于 Emby 缓存中的条目。

## 4. 目标用户流程

```text
配置连接/路径映射
        ↓
同步 Emby 元数据与文件索引
        ↓
选择资料库、规则和扫描深度
        ↓
候选生成：确定重复 / 高相似 / 异常
        ↓
按组查看证据、应用保留策略、人工复核
        ↓
生成 dry-run 报告与删除计划
        ↓
二次确认并进入安全执行队列
        ↓
逐项执行、确认结果、记录审计、刷新 Emby
```

默认原则：同步和扫描可以自动运行；删除默认必须人工确认；自动删除只允许在用户显式开启、规则为高置信度且路径策略通过校验时运行。

## 5. 功能需求

### P0：重构后必须具备

#### FR-01 多资料库与通用资源模型

- 支持 Emby 中所有可选资料库，不假设语言、国家、命名方式或资源类型。
- 资源模型至少包含：Emby 实例、资料库、条目、媒体源、文件/STRM 路径、作品身份、媒体流、图片资产、同步时间和数据来源。
- 记录原始 Emby JSON，但对扫描使用规范化字段；Schema 必须有版本和迁移机制。
- 同一资源可被多个资料库或条目引用，不能仅以 `emby_id` 作为“文件唯一身份”。

#### FR-02 同步与索引

- 支持全量同步、按资料库同步、增量同步和失败后继续。
- 显示每个阶段进度：Emby 拉取、文件检查、指纹计算、规则扫描、结果落库。
- 保留同步快照、开始/结束时间、条目数、失效数、错误数和数据新鲜度。
- 对 Emby API 不可提供的字段显示“未知”，不能用 0 或空值伪装为真实结论。

#### FR-03 分层查重

扫描结果必须区分以下类型，不能混成一个“重复”列表：

1. **实体引用重复**：多个 Emby 条目指向同一文件、同一 STRM 或同一真实路径。
2. **内容完全重复**：文件内容 hash 相同，但路径、文件名或资料库不同。
3. **媒体流重复**：容器不同但视频/音频流指纹相同，适用于转封装和重复 remux。
4. **作品身份重复**：Provider ID、番号、季/集、标题归一化后指向同一作品。
5. **版本重复**：同一作品存在不同分辨率、编码、字幕、剪辑或发行版本，由保留策略选择。
6. **名称/时长/大小疑似重复**：只有弱证据时标记为疑似，不得默认自动删除。
7. **图片资产重复**：图片二进制 hash 相同或感知相似，支持按同一作品、同一资料库和跨资料库分组。

候选必须带证据字段，例如：匹配算法、匹配键、相似度、参与字段、指纹状态、扫描时间和规则版本。

#### FR-04 图片与媒体完整性检查

- 检测 Primary、Backdrop、Logo、Thumb 等图片是否存在、是否可访问、是否为空或损坏。
- 对 Emby 图片资产保存类型、ImageTag、URL/本地来源和内容 hash；图片无法下载时标记为“未验证”。
- 支持图片精确重复 hash 与感知 hash 两类规则；感知相似只进入人工复核或可配置阈值。
- 能发现同一作品图片错配、多个条目共用不合理图片、跨资料库图片重复等问题。
- 默认不删除图片文件，只提供修复对象和来源信息；图片修复仍由 MDC 或用户确认的工具执行。

#### FR-05 筛选与规则

- 筛选条件至少包括：实例、资料库、路径前缀、文件/STRM 类型、媒体类型、标题、Provider ID、标签、年份、季/集、分辨率、编码、音频、字幕、时长、大小、图片状态、同步时间和风险等级。
- 规则可组合为“全部满足/任一满足”，支持保存、复制、启用/停用和规则版本。
- 支持每个资料库单独配置保留优先级，例如清晰度、编码、字幕语言、音轨、文件大小、路径来源、创建时间和观看状态。
- 支持排除项：资料库、目录、文件名模式、Provider ID、标签、作品组和人工忽略记录。
- 规则结果必须可解释：为何成组、为何推荐保留、为何推荐删除、为何必须人工确认。

#### FR-06 审核、报告与删除计划

- 结果按候选组展示，组内并列显示路径、大小、时长、分辨率、编码、字幕、Provider ID、图片状态、来源和匹配证据。
- 支持逐项保留/删除/忽略、整组选择、批量选择、备注和审核人/时间记录。
- 支持 dry-run：只生成将要处理的对象、预计释放空间、风险和阻塞项，不调用删除接口。
- 支持导出 JSON/CSV/Markdown 报告，报告包含扫描配置、规则版本和数据快照时间。
- 删除前执行路径映射和对象类型校验；默认只允许加入队列，不直接并发删除。
- 删除队列可暂停、继续、重试、取消未执行项；每个项目记录请求、Emby 返回、确认轮询、刷新和错误。
- 对 STRM/远程资源提供独立策略：仅删 Emby 条目、删 STRM、删源文件、跳过。默认策略为跳过源文件并要求显式选择。

#### FR-07 任务、通知与观测

- 支持同步任务、扫描任务、指纹任务和删除任务分开调度，避免一次大任务阻塞全部操作。
- 任务状态持久化，服务重启后可恢复到待继续/需重试，而不是依赖进程内存。
- 支持 Webhook/飞书或其他通知适配器，但通知失败不能影响核心任务状态。
- 日志分级、按任务过滤、保留错误上下文和结果摘要；敏感信息不得写入日志。
- 提供健康检查、数据新鲜度、最近任务、队列积压、失败率和存储占用。

#### FR-08 FNOS 安全与部署

- 兼容 FNOS Docker/Compose 和 `linux/amd64`、`linux/arm64`。
- 配置数据、数据库、索引和报告必须通过 `/data` 持久化；启动时检查挂载并给出明确告警。
- 支持 Emby API Token；用户名/密码如保留，必须加密或通过外部 Secret 注入，不能明文进入导出文件或日志。
- 支持应用级登录或至少提供反向代理/局域网/Tailscale 部署约束说明。
- API 默认不暴露公网；删除、导入配置、路径扫描和凭据读取需要权限控制。
- 支持只读模式：只同步、扫描、报告，不提供删除和写入接口。

### P1：建议在核心闭环稳定后增加

- 多 Emby 实例/多服务器，以及跨实例重复检测。
- 本地文件系统扫描适配器和路径映射管理；支持只读挂载。
- 分阶段指纹策略：快速元数据筛选 → 部分 hash → 全文件 hash → 媒体流/图片感知 hash。
- 视频关键帧/音频指纹，用于同内容不同压制或片段重复的人工复核。
- 作品合并视图：同 Provider ID、同系列、同季集、同番号的所有版本统一展示。
- 规则测试器：输入两条或一组样例，解释为什么成组或不成组。
- 回收站/隔离目录、删除前备份清单和有限时间内恢复辅助。
- Emby Webhook 触发的局部重同步，而不是每次全库同步。
- 资源质量评分、观看历史/收藏/播放次数参与保留建议。
- 只读 API 与导出接口，供 FNOS 首页、监控或个人自动化调用。

### P2：可选探索

- OCR/字幕内容相似度、视频场景相似度和跨语言标题实体识别。
- 多用户保留策略和共享资料库审批流。
- 分布式指纹 worker；当前单 FNOS 节点不建议一开始引入。
- WebDAV/CloudDrive2/115 原生资源探测；需先明确 API、权限和删除语义。

## 6. 推荐查重引擎设计

### 6.1 候选生成顺序

为了适配 FNOS 的云盘/STRM 场景，不能默认对所有资源下载并计算完整 hash。建议使用多阶段管线：

1. Emby 元数据候选：Provider ID、番号、系列/季集、归一化标题。
2. 文件元数据候选：路径、扩展名、大小、时长、分辨率、流信息。
3. 快速指纹：文件头、首尾块、固定采样块；仅对候选组计算。
4. 全文件 hash：仅对高价值、可访问、用户开启的对象执行。
5. 媒体流/图片感知指纹：只对仍无法判定或明确选择的候选组执行。

### 6.2 置信度分级

- `exact`：同文件引用或内容 hash 完全一致，可进入高置信度候选。
- `strong`：Provider ID/番号/季集一致，且时长或媒体流高度一致。
- `similar`：标题、时长、大小、版本标签等多个弱证据一致。
- `unknown`：数据缺失、远程不可访问或指纹未完成；不得推荐自动删除。

只有 `exact` 或用户明确配置的 `strong` 规则允许进入自动处理候选；`similar` 和 `unknown` 默认人工复核。

## 7. 数据与模块建议

重构建议拆分为以下模块，避免继续把同步、扫描、删除和 Web 路由集中在一个文件：

- `connectors/emby`：Emby API、认证、分页、Webhook。
- `connectors/filesystem`：只读文件检查、路径映射、STRM 识别。
- `connectors/images`：图片拉取、完整性检查、hash/pHash。
- `indexer`：资源规范化、快照、增量更新、数据新鲜度。
- `fingerprints`：媒体/文件/图片指纹和缓存。
- `rules`：规则 DSL、候选分组、评分、保留建议、版本化。
- `jobs`：可恢复任务、队列、并发限制、暂停/重试。
- `review`：审核状态、备注、忽略、报告和删除计划。
- `actions`：Emby 删除/刷新、文件策略、dry-run、审计。
- `web`：API、前端、权限和静态资源。
- `storage`：SQLite schema、迁移、备份、导出。

SQLite 仍可作为单节点默认存储，但必须先加入迁移版本、任务状态、扫描快照、指纹缓存、审计记录和规则版本表；暂不建议为了“未来多节点”直接引入复杂数据库。

## 8. 非功能需求

- 安全：默认只读、删除显式确认、敏感信息脱敏、路径越界保护、操作审计。
- 可恢复：大任务可重启续跑；索引、指纹和删除队列不因容器更新丢失。
- 可解释：每个候选和推荐都有证据和规则版本。
- 性能：大库扫描分阶段、可暂停、可限速；避免一次性把全部条目和图片载入内存。
- 兼容：FNOS Docker、ARM64/AMD64、现有 `/data` 数据迁移和当前 Emby API。
- 可测试：规则纯函数测试、Emby API mock、SQLite migration test、删除 worker 状态测试、前端关键行为测试。
- 可观测：任务进度、失败原因、数据新鲜度、候选数量和删除结果均可读回。

## 9. 迁移与交付阶段

### Phase 0：需求与只读审计

- 复核当前 FNOS 容器、Compose、挂载、Emby 资料库、CMS/MDC 目录和访问权限。
- 明确媒体删除对象：Emby 条目、STRM、本地实体文件、云端源文件分别如何处理。
- 选定第一批资料库和代表性样本，覆盖日本、欧美/其他类型、STRM 和本地文件。

### Phase 1：新索引与规则内核

- 保留现有 Emby API 同步和删除队列行为。
- 引入版本化资源模型、扫描快照、通用身份/文件/图片字段。
- 先实现 exact/strong/similar/unknown 分层和 dry-run，不开启自动删除。

### Phase 2：审核与安全执行

- 重做结果页、证据展示、规则测试器、报告和删除计划。
- 实现路径映射、对象类型策略、只读模式、暂停/恢复和完整审计。
- 用一个小资料库完成真实链路验证，再扩大扫描范围。

### Phase 3：FNOS 集成与性能

- 接入只读文件检查、图片指纹、增量扫描和通知。
- 对 STRM/云端资源做不可访问和删除策略验证。
- 在真实 FNOS 上验证升级、备份恢复、重启续跑和 ARM64 镜像。

## 10. 验收标准（初版）

1. 在不依赖日本番号的前提下，能够对至少两个不同类型资料库完成同步，并将确定重复、疑似重复、缺失图片、缺失元数据分别展示。
2. 对一个同时包含本地文件、STRM 和跨资料库引用的样本，系统能明确指出匹配证据、指纹状态和删除对象，不把“删除 Emby 条目”误报为“删除源文件”。
